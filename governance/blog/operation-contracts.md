# Контракты операций и будущей проекции в Hugo

Этот документ — замороженный вход для реализации. Любая будущая работа в
шаблонах сначала сверяется с ним и с инвариантами.

## Контракт создания заметки

Новая заметка создаётся как `Note` со следующими метаданными:

```yaml
id: gslb-effective-state
translationKey: gslb-effective-state
kind: note
date: 2026-08-23
occurredAt: 2026-08-23 # необязательно; только если событие было раньше публикации
draft: true
summary: "Кратко: что именно сдвинулось."
projects: [gslb-ui]       # допустим пустой список
threads: [scenario-first-ux] # допустим пустой список
tags: [gslb, ux]
artifacts: []
```

Тело заметки отвечает на четыре вопроса в любом естественном порядке:
контекст, локальная находка/решение, свидетельство или ход эксперимента,
граница знания либо следующий вопрос. Это шаблон мышления, не требование к
длине или формату.

## Контракт создания страницы проекта

Страница проекта создаётся, когда есть либо две опубликованные связанные
заметки, либо реальная активная работа, которой нужна живая карта. До этого
`projects: [id]` остаётся кандидатом и не создаёт страницы автоматически.

Минимальные данные страницы:

```yaml
id: gslb-ui
translationKey: gslb-ui
kind: project
state: active
visibility: listed
started: 2026-08-23
nextQuestion: "Как сценарии объясняют владение пробами?"
```

Текст описывает объект/намерение и текущую рамку. Список заметок и артефактов
строится автоматически по `id`; он не редактируется вручную.

## Контракт продвижения исследовательской линии

1. Первая заметка использует ключ в `threads` и показывается только как тег.
2. После трёх содержательных опубликованных заметок, связанных одним
   повторяющимся вопросом или методом, линия может стать `ResearchThread`.
   Порог — разрешение создать страницу, не автоматическое обязательство.
3. Для страницы требуются `id`, `kind: research-thread`, `state: promoted`,
   область применимости и явная граница («не обо всём product management»).
4. Ссылка «Research threads» появляется в основной навигации, когда есть две
   продвинутые линии либо одна явно `featured`. До этого линии доступны со
   связанных заметок, страницы проекта и главной.

## Контракт синтеза

`CaseStudy` создаётся, когда есть закрытый участок траектории: исходная
проблема, совершённые выборы, результат или текущее ограничение и вывод.
Число заметок не является порогом. `Essay` использует ту же трассируемость, но
может собирать материалы из нескольких проектов или независимых заметок.

Обычный порядок связанного материала — по `occurredAt`, если поле задано, и
по `date` в остальных случаях. Так поздно опубликованная заметка о раннем
эксперименте не искажает историю проекта. Редакторская подборка допустима
только как отдельный блок `featured`, а не как замена полного вычисленного
списка.

## Требования к проекции в сайт

Будущая реализация должна добавить канонические страницы:

| Поверхность | Источник | Правило показа |
| --- | --- | --- |
| `/notes/` | опубликованные `Note` | всегда, обратная хронология |
| `/projects/` | страницы `Project` | только `listed` и `featured` |
| `/projects/{id}/` | одна страница `Project` + связи | заметки/артефакты вычислены из front matter |
| `/threads/{id}/` | одна страница `ResearchThread` + связи | только `promoted` |
| `/case-studies/` | опубликованные `CaseStudy` | появляется при первой такой публикации |
| `/essays/` | опубликованные `Essay` | появляется при первой такой публикации |
| главная | все опубликованные `Publication` | лента + ограниченные выборки коллекций |

Для этого нужны отдельные типы/архетипы страниц и Hugo-шаблоны, которые
фильтруют публикации по `Params.projects` и `Params.threads`. `Project` и
`ResearchThread` не следует реализовывать как Hugo taxonomies: их страницы
имеют собственный текст, состояние и жизненный цикл. `tags` можно оставить
обычной taxonomy.

Файловая схема, которую должна принять реализация:

```text
content/<lang>/notes/<id>.md
content/<lang>/projects/<id>/_index.md
content/<lang>/threads/<id>/_index.md
content/<lang>/case-studies/<id>.md
content/<lang>/essays/<id>.md
```

Главное меню не должно быть полностью статичным в `hugo.yaml`: пункты
`Projects`, `Case studies` и `Research threads` выводятся при наличии их
видимых множеств. Постоянный минимум — Home, Notes и About.

## Проверки перед публикацией

- все `id` уникальны в пределах логической сущности и совпадают у переводов;
- каждый ID в `projects`, `threads`, `artifacts` имеет допустимый формат;
- опубликованные страницы проектов и линий проходят минимальный контракт;
- все ссылки `synthesizes` разрешаются в существующую публикацию либо имеют
  явно зафиксированное закрытое исключение;
- списки на проектных и thread-страницах совпадают с вычисленными связями.
