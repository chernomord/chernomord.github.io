# Совместимость Hugo и темы

Этот документ определяет техническую границу для блога. Он не меняет его
редакционную модель, но не позволяет реализации опираться на удалённый API
Hugo или на неявное поведение темы.

## Поддерживаемая граница

- Hugo: версия из локального `hugo version`; на момент принятия — `0.164.0`.
- Тема: Hugo PaperMod, точная версия закреплена в `go.mod`.
- Локальные шаблоны в `layouts/` имеют приоритет над шаблонами темы и являются
  узкими compatibility overrides, а не новым дизайном темы.

PaperMod на закреплённом коммите `d3768854` использует удаляемые языковые
методы Hugo. Локальные копии `baseof.html`, `header.html`,
`translation_list.html`, `templates/opengraph.html` и `rss.xml` заменяют их
на `Direction`, `Label` и `Locale` соответственно.

## Front matter

`kind`, `lang` и `path` зарезервированы или удалены Hugo и не применяются как
пользовательские поля. Семантический тип нашей модели записывается только в
`blogKind` и читается в шаблонах как `.Params.blogKind`.

`type` также не является заменой `blogKind`: это штатный механизм Hugo для
выбора шаблонов, а не редакционная классификация публикации.

## Обязательная проверка

Перед изменением Hugo, PaperMod, front matter или локальных шаблонов:

1. Сверить поддерживаемые API с официальной документацией Hugo и release notes
   целевой версии.
2. Выполнить `hugo build --logLevel info`.
3. Проверить, что в выводе нет `deprecated`, `WARN` или `ERROR`.
4. Просканировать проект на удалённые поля:

   ```text
   ^kind:|^lang:|^path:|\.Language\.(LanguageDirection|LanguageName|LanguageCode)
   ```

5. При обновлении PaperMod сопоставить каждый локальный override с новой
   верcией исходного шаблона: перенести изменения темы, повторно применить
   только compatibility-замены и заново выполнить сборку.

Предупреждения не подавляются через `ignoreLogs`: они считаются сигналом
несовместимости, который нужно устранить либо явно документировать в ADR.
